Actividad 3 - Semana 3

En esta actividad se desarrollan los ejercicios correspondientes a la Semana 3 del curso de Base de Datos II, aplicando conceptos de diseño, creación y administración de bases de datos.

1. Implementación de la Base de Datos Grados y Títulos

Se implementa una base de datos orientada a la gestión de información relacionada con grados académicos, títulos, estudiantes, docentes, tesis y procesos de titulación.

Creación de la Base de Datos

Se crea la base de datos que permitirá almacenar y administrar la información correspondiente al sistema de Grados y Títulos.

Diseño de Tablas

Se diseñan las tablas necesarias para organizar la información y establecer las relaciones entre las diferentes entidades del sistema.

Esquemas

Se utilizan esquemas para organizar las tablas y objetos de la base de datos de acuerdo con su función.

Restricciones

Se implementan restricciones como claves primarias, claves foráneas, valores únicos y condiciones de validación para mantener la integridad de los datos.

Script SQL completo - Grados y Títulos

-- ============================================ -- BASE DE DATOS: GRADOS Y TÍTULOS -- ============================================ CREATE DATABASE GradosTitulosUPLA; GO USE GradosTitulosUPLA; GO -- ============================================ -- ESQUEMAS -- ============================================ CREATE SCHEMA Academico; GO CREATE SCHEMA Tesis; GO -- ============================================ -- TABLAS DEL ESQUEMA ACADEMICO -- ============================================ CREATE TABLE Academico.Facultad ( FacultadID INT IDENTITY(1,1) PRIMARY KEY, Nombre NVARCHAR(100) NOT NULL, Codigo NVARCHAR(10) UNIQUE NOT NULL ); GO CREATE TABLE Academico.ProgramaEstudios ( ProgramaID INT IDENTITY(1,1) PRIMARY KEY, FacultadID INT NOT NULL, Nombre NVARCHAR(150) NOT NULL, GradoAcademico NVARCHAR(100), TituloProfesional NVARCHAR(100), CONSTRAINT FK_Programa_Facultad FOREIGN KEY (FacultadID) REFERENCES Academico.Facultad(FacultadID) ); GO CREATE TABLE Academico.Bachiller ( BachillerID INT IDENTITY(1,1) PRIMARY KEY, DNI NVARCHAR(8) UNIQUE NOT NULL, Nombres NVARCHAR(100) NOT NULL, Apellidos NVARCHAR(100) NOT NULL, ProgramaID INT NOT NULL, FechaGrado DATE, Estado NVARCHAR(20) DEFAULT 'Egresado', CONSTRAINT FK_Bachiller_Programa FOREIGN KEY (ProgramaID) REFERENCES Academico.ProgramaEstudios(ProgramaID), CONSTRAINT CHK_EstadoBachiller CHECK (Estado IN ('Egresado', 'Bachiller', 'Titulado')) ); GO -- ============================================ -- TABLAS DEL ESQUEMA TESIS -- ============================================ CREATE TABLE Tesis.Asesor ( AsesorID INT IDENTITY(1,1) PRIMARY KEY, DNI NVARCHAR(8) UNIQUE NOT NULL, Nombres NVARCHAR(100) NOT NULL, Apellidos NVARCHAR(100) NOT NULL, CodigoORCID NVARCHAR(20), Especialidad NVARCHAR(100) ); GO CREATE TABLE Tesis.PlanTesis ( PlanID INT IDENTITY(1,1) PRIMARY KEY, BachillerID INT NOT NULL, AsesorID INT NOT NULL, Titulo NVARCHAR(200) NOT NULL, LineaInvestigacion NVARCHAR(150), FechaInicio DATE, FechaFin DATE, Estado NVARCHAR(20) DEFAULT 'En Ejecucion', CONSTRAINT FK_Plan_Bachiller FOREIGN KEY (BachillerID) REFERENCES Academico.Bachiller(BachillerID), CONSTRAINT FK_Plan_Asesor FOREIGN KEY (AsesorID) REFERENCES Tesis.Asesor(AsesorID), CONSTRAINT CHK_Fechas CHECK (FechaFin > FechaInicio) ); GO CREATE TABLE Tesis.Jurado ( JuradoID INT IDENTITY(1,1) PRIMARY KEY, DNI NVARCHAR(8) UNIQUE NOT NULL, Nombres NVARCHAR(100) NOT NULL, Apellidos NVARCHAR(100) NOT NULL, GradoAcademico NVARCHAR(50) ); GO CREATE TABLE Tesis.Sustentacion ( SustentacionID INT IDENTITY(1,1) PRIMARY KEY, PlanID INT NOT NULL, FechaSustentacion DATETIME, NotaFinal DECIMAL(4,2), Resultado NVARCHAR(20), CONSTRAINT FK_Sustentacion_Plan FOREIGN KEY (PlanID) REFERENCES Tesis.PlanTesis(PlanID), CONSTRAINT CHK_Nota CHECK (NotaFinal BETWEEN 0 AND 20) ); GO

2. Cadena Editorial

Se desarrolla el modelo correspondiente a una cadena editorial, identificando las entidades, atributos y relaciones necesarias para representar la información dentro de una base de datos.

Entidades

Se identifican las principales entidades que participan en el funcionamiento de la cadena editorial.

Relaciones

Se establecen las relaciones entre las entidades para representar correctamente el funcionamiento del sistema.

Base de Datos

El modelo puede ser implementado mediante tablas, claves primarias y claves foráneas.

Script SQL completo - Cadena Editorial

-- ============================================ -- BASE DE DATOS: CADENA EDITORIAL -- ============================================ CREATE DATABASE CadenaEditorial; GO USE CadenaEditorial; GO -- ============================================ -- SUCURSALES -- ============================================ CREATE TABLE Sucursal ( CodigoSucursal INT PRIMARY KEY, Domicilio NVARCHAR(200), Telefono NVARCHAR(20) ); GO -- ============================================ -- EMPLEADOS (Trabajan en una única sucursal) -- ============================================ CREATE TABLE Empleado ( NIF NVARCHAR(15) PRIMARY KEY, Nombre NVARCHAR(50) NOT NULL, Apellidos NVARCHAR(50) NOT NULL, Telefono NVARCHAR(20), CodigoSucursal INT NOT NULL, CONSTRAINT FK_Empleado_Sucursal FOREIGN KEY (CodigoSucursal) REFERENCES Sucursal(CodigoSucursal) ); GO -- ============================================ -- REVISTAS -- ============================================ CREATE TABLE Revista ( NumeroRegistro INT PRIMARY KEY, Titulo NVARCHAR(100) NOT NULL, Periodicidad NVARCHAR(50), Tipo NVARCHAR(50) ); GO -- ============================================ -- PUBLICACION (Relación N:M entre Sucursal y Revista) -- ============================================ CREATE TABLE Publicacion ( CodigoSucursal INT NOT NULL, NumeroRegistro INT NOT NULL, PRIMARY KEY (CodigoSucursal, NumeroRegistro), CONSTRAINT FK_Publicacion_Sucursal FOREIGN KEY (CodigoSucursal) REFERENCES Sucursal(CodigoSucursal), CONSTRAINT FK_Publicacion_Revista FOREIGN KEY (NumeroRegistro) REFERENCES Revista(NumeroRegistro) ); GO -- ============================================ -- PERIODISTAS (No trabajan en sucursales) -- ============================================ CREATE TABLE Periodista ( NIF NVARCHAR(15) PRIMARY KEY, Nombre NVARCHAR(50) NOT NULL, Apellidos NVARCHAR(50) NOT NULL, Telefono NVARCHAR(20), Especialidad NVARCHAR(100) ); GO -- ============================================ -- ARTICULOS (Relación N:M entre Periodista y Revista) -- ============================================ CREATE TABLE Articulo ( IDArticulo INT IDENTITY(1,1) PRIMARY KEY, NIF_Periodista NVARCHAR(15) NOT NULL, NumeroRegistro INT NOT NULL, TituloArticulo NVARCHAR(150), CONSTRAINT FK_Articulo_Periodista FOREIGN KEY (NIF_Periodista) REFERENCES Periodista(NIF), CONSTRAINT FK_Articulo_Revista FOREIGN KEY (NumeroRegistro) REFERENCES Revista(NumeroRegistro) ); GO -- ============================================ -- SECCIONES FIJAS (Dependen de Revista) -- ============================================ CREATE TABLE SeccionFija ( IDSeccion INT IDENTITY(1,1) PRIMARY KEY, NumeroRegistro INT NOT NULL, Titulo NVARCHAR(100) NOT NULL, Extension NVARCHAR(50), CONSTRAINT FK_Seccion_Revista FOREIGN KEY (NumeroRegistro) REFERENCES Revista(NumeroRegistro) ); GO -- ============================================ -- EJEMPLARES (Dependen de Revista) -- ============================================ CREATE TABLE Ejemplar ( IDEjemplar INT IDENTITY(1,1) PRIMARY KEY, NumeroRegistro INT NOT NULL, Fecha DATE, NumeroPaginas INT, EjemplaresVendidos INT, CONSTRAINT FK_Ejemplar_Revista FOREIGN KEY (NumeroRegistro) REFERENCES Revista(NumeroRegistro) ); GO

3. Empresa de Material Informático

Se desarrolla el modelo de datos para una empresa dedicada a la comercialización de material informático, considerando las entidades y relaciones necesarias para gestionar su información.

Productos

Se considera la información relacionada con los materiales y productos informáticos comercializados por la empresa.

Clientes

Se registra la información necesaria para identificar y gestionar a los clientes de la empresa.

Relaciones

Se establecen las relaciones entre las diferentes entidades para organizar correctamente los datos.

Script SQL completo - Empresa de Material Informático

-- ============================================ -- BASE DE DATOS: EMPRESA DE MATERIAL INFORMÁTICO -- ============================================ CREATE DATABASE EmpresaInformatica; GO USE EmpresaInformatica; GO -- ============================================ -- SECCIONES -- ============================================ CREATE TABLE Seccion ( IDSeccion INT PRIMARY KEY, NombreSeccion NVARCHAR(100) NOT NULL ); GO -- ============================================ -- EMPLEADOS (Trabajan en una única sección) -- ============================================ CREATE TABLE Empleado ( NIF NVARCHAR(15) PRIMARY KEY, Nombre NVARCHAR(50) NOT NULL, Apellidos NVARCHAR(50) NOT NULL, IDSeccion INT NOT NULL, CONSTRAINT FK_Empleado_Seccion FOREIGN KEY (IDSeccion) REFERENCES Seccion(IDSeccion) ); GO -- ============================================ -- CLIENTES -- ============================================ CREATE TABLE Cliente ( NIF NVARCHAR(15) PRIMARY KEY, Nombre NVARCHAR(50) NOT NULL, Apellidos NVARCHAR(50) NOT NULL, Domicilio NVARCHAR(200), Ciudad NVARCHAR(50), Provincia NVARCHAR(50), Telefono NVARCHAR(20) ); GO -- ============================================ -- EQUIPOS -- ============================================ CREATE TABLE Equipo ( CodigoEquipo INT PRIMARY KEY, Descripcion NVARCHAR(200) NOT NULL, Precio DECIMAL(10,2) NOT NULL, Stock INT DEFAULT 0 ); GO -- ============================================ -- COMPONENTES -- ============================================ CREATE TABLE Componente ( CodigoComponente INT PRIMARY KEY, Descripcion NVARCHAR(200) NOT NULL, Precio DECIMAL(10,2) NOT NULL, Stock INT DEFAULT 0 ); GO -- ============================================ -- COMPRAS (Cabecera de la compra) -- ============================================ CREATE TABLE Compra ( IDCompra INT IDENTITY(1,1) PRIMARY KEY, NIF_Cliente NVARCHAR(15) NOT NULL, NIF_Empleado NVARCHAR(15) NOT NULL, FechaCompra DATETIME DEFAULT GETDATE(), CONSTRAINT FK_Compra_Cliente FOREIGN KEY (NIF_Cliente) REFERENCES Cliente(NIF), CONSTRAINT FK_Compra_Empleado FOREIGN KEY (NIF_Empleado) REFERENCES Empleado(NIF) ); GO -- ============================================ -- DETALLE COMPRA EQUIPO (Histórico) -- ============================================ CREATE TABLE DetalleCompraEquipo ( IDCompra INT NOT NULL, CodigoEquipo INT NOT NULL, Cantidad INT NOT NULL, PRIMARY KEY (IDCompra, CodigoEquipo), CONSTRAINT FK_DetalleEquipo_Compra FOREIGN KEY (IDCompra) REFERENCES Compra(IDCompra), CONSTRAINT FK_DetalleEquipo_Equipo FOREIGN KEY (CodigoEquipo) REFERENCES Equipo(CodigoEquipo) ); GO -- ============================================ -- DETALLE COMPRA COMPONENTE (Histórico) -- ============================================ CREATE TABLE DetalleCompraComponente ( IDCompra INT NOT NULL, CodigoComponente INT NOT NULL, Cantidad INT NOT NULL, PRIMARY KEY (IDCompra, CodigoComponente), CONSTRAINT FK_DetalleComp_Compra FOREIGN KEY (IDCompra) REFERENCES Compra(IDCompra), CONSTRAINT FK_DetalleComp_Componente FOREIGN KEY (CodigoComponente) REFERENCES Componente(CodigoComponente) ); GO -- ============================================ -- COMPOSICION DE EQUIPOS -- (Un equipo consta de varios componentes) -- ============================================ CREATE TABLE ComposicionEquipo ( CodigoEquipo INT NOT NULL, CodigoComponente INT NOT NULL, CantidadNecesaria INT NOT NULL, PRIMARY KEY (CodigoEquipo, CodigoComponente), CONSTRAINT FK_Composicion_Equipo FOREIGN KEY (CodigoEquipo) REFERENCES Equipo(CodigoEquipo), CONSTRAINT FK_Composicion_Componente FOREIGN KEY (CodigoComponente) REFERENCES Componente(CodigoComponente) ); GO

4. Conceptos Aplicados

  • Creación de bases de datos.
  • Creación de esquemas mediante CREATE SCHEMA.
  • Diseño y creación de tablas.
  • Claves primarias (PRIMARY KEY).
  • Claves foráneas (FOREIGN KEY).
  • Restricciones de integridad.
  • Relaciones entre tablas.
  • Organización de la información mediante esquemas.

¿Qué aprendí?

Durante la Semana 3 aprendí a aplicar conceptos de diseño y administración de bases de datos. También reforcé el uso de SQL para crear bases de datos, esquemas y tablas, además de implementar restricciones que permiten mantener la integridad de la información.

Además, comprendí la importancia de establecer correctamente las relaciones entre las tablas para organizar la información y facilitar su administración dentro de una base de datos.
